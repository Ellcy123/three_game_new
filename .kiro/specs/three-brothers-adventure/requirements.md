# 需求文档

## 简介

《三兄弟的冒险2》是一款基于网页的三人在线文字冒险游戏（TRPG风格）。三名玩家分别扮演猫、狗、乌龟，通过输入关键词组合来探索世界、解开谜题、战胜敌人。游戏主题是关于宠物死后世界的温情故事，探讨爱与回响的永恒主题。

本文档定义了游戏核心系统的需求，聚焦于Phase 1核心系统和Phase 2第一关内容的实现。

## 术语表

- **游戏系统**: 三兄弟冒险游戏的核心运行系统
- **玩家**: 参与游戏的用户，最多3人同时在线
- **角色**: 玩家控制的游戏角色（猫/狗/乌龟）
- **关键词组合**: 玩家输入的道具或角色组合，格式为"A+B"
- **事件**: 由关键词组合触发的游戏事件
- **游戏状态**: 游戏当前的完整状态，包括角色状态、已触发事件、收集的道具等
- **房间**: 多人游戏房间，容纳3名玩家
- **回合**: 玩家轮流行动的基本单位
- **生命值**: 角色生命值，初始为8点

## 需求列表

### 需求1：房间管理

**用户故事：** 作为玩家，我希望能够创建或加入游戏房间，以便与两位朋友一起在线游戏。

#### 验收标准

1. 当玩家请求创建房间时，游戏系统应生成唯一的房间代码，并创建一个新房间，该玩家作为第一个成员
2. 当玩家输入有效的房间代码时，如果房间人数少于3人，游戏系统应将该玩家加入对应房间
3. 当玩家尝试加入已满的房间时，游戏系统应拒绝加入请求并显示房间已满的错误信息
4. 当房间恰好有3名玩家时，游戏系统应为所有玩家启用游戏开始选项
5. 当玩家从房间断开连接时，游戏系统应通知其他玩家并暂停游戏，直到重新连接或超时

### 需求2：角色分配

**用户故事：** 作为玩家，我希望被分配一个神秘角色，以便在游戏过程中逐渐发现角色的真实身份。

#### 验收标准

1. 当玩家加入房间时，游戏系统应显示三个神秘角色（角色1、角色2、角色3），不透露具体动物类型
2. 当玩家选择一个角色编号时，游戏系统应将该角色分配给玩家，内部记录对应的动物类型（猫/狗/乌龟），但不向玩家显示
3. 当玩家为角色输入自定义名称时，游戏系统应更新角色显示名称
4. 当所有3名玩家都选择了角色时，游戏系统应为所有玩家启用游戏准备确认
5. 当游戏剧情揭示角色身份时，游戏系统应向对应玩家显示其角色的真实动物类型和特殊能力

### 需求3：关键词组合系统

**用户故事：** 作为玩家，我希望通过输入关键词组合与游戏世界互动，以便探索、解谜并推进故事。

#### 验收标准

1. 当玩家提交格式为"A+B"的关键词组合时，游戏系统应解析输入并将同义词标准化为标准关键词
2. 当有效的关键词组合匹配到已定义的事件时，游戏系统应触发相应事件并更新游戏状态
3. 当关键词组合不匹配任何已定义事件时，游戏系统应显示无效果的提示信息
4. 当解析关键词输入时，游戏系统应识别角色同义词（猫=天一=玩家1=角色1=猫咪）并标准化为标准标识符
5. 当序列化关键词组合进行存储时，游戏系统应转换为规范的字符串格式
6. 当反序列化存储的关键词组合时，游戏系统应重建具有等效语义含义的原始组合对象

### 需求4：回合制系统

**用户故事：** 作为玩家，我希望与其他玩家轮流行动，以便游戏有序进行。

#### 验收标准

1. 当游戏回合开始时，游戏系统应按顺序指定第一个玩家为当前行动玩家
2. 当当前行动玩家提交关键词组合时，游戏系统应处理该行动并将回合推进到下一个玩家
3. 当玩家尝试在非自己回合时行动，游戏系统应拒绝该行动并通知玩家等待自己的回合
4. 当所有玩家都完成一次行动时，游戏系统应增加回合计数器并开始新的回合

### 需求5：生命值系统

**用户故事：** 作为玩家，我希望追踪角色的生命值，以便了解生存状态并做出战略决策。

#### 验收标准

1. 当游戏开始时，游戏系统应为每个角色初始化8点生命值
2. 当事件修改生命值时，游戏系统应更新角色生命值并向所有玩家广播变化
3. 当角色生命值降至零时，游戏系统应将角色标记为阵亡并通知所有玩家
4. 当另一个玩家选择复活阵亡角色时，游戏系统应从复活者扣除2点生命值，并将阵亡角色恢复到1点生命值
5. 在第一关（密室逃脱）期间，游戏系统应防止角色生命值降至1点以下

### 需求6：事件系统

**用户故事：** 作为玩家，我希望游戏事件根据我的行动和游戏状态触发，以便故事动态推进。

#### 验收标准

1. 当事件被触发时，游戏系统应在执行事件前检查所有前置条件是否满足
2. 当一次性事件被触发时，游戏系统应将事件标记为已完成并防止重复触发
3. 当可重复事件被触发时，游戏系统应执行事件而不标记完成状态
4. 当事件执行完成时，游戏系统应更新游戏状态，包括所有效果（获得道具、解锁区域、生命值变化、剧情文本）
5. 当序列化游戏状态进行持久化时，游戏系统应将所有状态数据转换为JSON格式
6. 当反序列化存储的游戏状态时，游戏系统应重建包含所有已触发事件和已收集道具的完整状态对象

### 需求7：实时同步

**用户故事：** 作为玩家，我希望实时看到其他玩家的行动，以便我们能够有效协作。

#### 验收标准

1. 当任何玩家执行行动时，游戏系统应在500毫秒内向房间内所有玩家广播该行动及结果
2. 当游戏状态发生变化时，游戏系统应将更新后的状态同步到所有已连接的玩家
3. 当玩家断线后重新连接时，游戏系统应向重连玩家恢复完整的当前游戏状态
4. 当网络延迟超过2秒时，游戏系统应向受影响的玩家显示连接警告

### 需求8：第一关 - 密室逃脱

**用户故事：** 作为玩家，我希望在密室关卡中解谜，以便收集字母并与队友一起逃脱。

#### 验收标准

1. 当第一关开始时，游戏系统应初始化密室场景，包含所有可交互对象和区域
2. 当玩家触发揭示字母的事件时，游戏系统应将字母（C、E、H或O）添加到团队物品栏并显示发现信息
3. 当玩家在门口提交密码"ECHO"时，游戏系统应验证是否已收集全部4个字母，如果有效则解锁出口
4. 当出口解锁时，游戏系统应将所有玩家转移到第二关并保存进度
5. 当加载第一关配置时，游戏系统应从JSON配置文件解析事件定义
6. 当保存第一关进度时，游戏系统应将当前状态序列化到持久存储

### 需求9：游戏状态持久化

**用户故事：** 作为玩家，我希望游戏进度能够保存，以便稍后继续游戏。

#### 验收标准

1. 当重要游戏事件发生时，游戏系统应自动保存当前游戏状态
2. 当玩家请求加载已保存的游戏时，游戏系统应恢复完整的游戏状态，包括所有玩家位置、物品栏和进度
3. 当保存游戏状态时，游戏系统应将所有游戏数据序列化为JSON格式进行存储
4. 当加载游戏状态时，游戏系统应反序列化JSON数据并重建所有具有正确关系的游戏对象

### 需求10：用户界面

**用户故事：** 作为玩家，我希望有一个清晰直观的界面，以便轻松理解游戏状态并输入命令。

#### 验收标准

1. 当显示游戏内容时，游戏系统应在不同的视觉区域显示剧情文本、玩家状态和可用行动
2. 当玩家在输入框中输入时，游戏系统应提供输入格式有效性的实时反馈
3. 当游戏事件发生时，游戏系统应以适当的视觉样式显示事件结果（伤害、治疗、发现使用不同颜色）
4. 当显示玩家状态时，游戏系统应为所有玩家显示角色名称、生命值和当前回合指示器
